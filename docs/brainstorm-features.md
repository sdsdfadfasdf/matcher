# StatusMatch Feature Brainstorm

Generated by 4 parallel agents (Product, Technical, Design/UX, Community).

---

## Top Ideas by Theme

### Data & Community (build a defensible moat)

| # | Feature | Effort | Why |
|---|---------|--------|-----|
| 1 | **Match Outcome Reports** — users submit approved/denied/pending, live matchRate recalculates | Med | Replaces static data with crowd-sourced truth. Enables #2, #3, #4 below. |
| 2 | **Regional Match Rate Breakdowns** — success rates segmented by user region | Med | Huge differentiator — no competitor does this. Geographic disparities are well-known in status matching. |
| 3 | **"People Also Pursued" Recommender** — cross-sell based on community data | Low-Med | Creates discovery loops organically. |
| 4 | **Community Tips (Upvoted)** — user-submitted tips replace static text | Low-Med | Self-maintaining content. |
| 5 | **Data Freshness Badges** — "verified X days ago" + community flagging for expired matches | Low | Solves the #1 trust issue: "is this match still active?" |

### Strategy & Discovery (make the app smarter)

| 10 | **Match Difficulty Score (computed)** — weighted 1-100 replacing static easy/medium/hard | Low | Transparent, trustworthy |

---

## Recommended First Phase

**Highest impact per effort:**

1. **Match Outcome Reports + Regional Breakdown** — this is the pivot from "static directory" to "community intelligence." It doesn't require a full backend; can start with localStorage + JSON export.
2. **Reverse Match Lookup** — one afternoon of work, dramatically improves first-time user experience.
3. **Data Freshness Badges + Community Flagging** — solves the trust problem immediately; pure client-side.
4. **Application Pipeline Tracker** — extends the existing profile system; gives users a reason to return.

These four together transform the app from a read-only directory into an interactive tool that gets smarter with every user action.
